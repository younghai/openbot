3. 한눈에: 강점 · 열위 · 전략

🟦 앞서는 축 (4)

· 주권 — 대화·키·모델 전부 내 머신
· 통제 — 모든 부작용 도구 실행 전 승인+전량 감사
· 개방성 — 임의 MCP(stdio 포함)·OpenAPI 즉시 연결
· 비용 — 구독 없음, 로컬 모델 0원, 전기세만

🟥 뒤처지는 축 (4)과 극복 경로

· 모델 품질 → BYO 키 즉시 해소 (경로 실측 완료)
· 채널 → Telegram 게이트웨이 2차 (승인 API 이미 준비됨)
· 접근성 → Electron 셸 (§4 dinobot 패턴)
· 확장 → 3차 멀티유저 (스키마는 추가 전용 설계)

종합 68점 산출: 12개 축을 "일상 에이전트 사용" 관점 가중(주권·통제·개방·비용 4축은 ×1.25, 나머지 ×0.9) 후 정규화. 단순 평균은 71 — 어느 쪽이든 "기능 열위+주권 우위"라는 구조는 동일하다.

4. dinobot-desktop 조사 — 우리 2차 로드맵의 실증 사례

2026-10-31 조사. dinobot-labs/dinobot-desktop(Electron 클라이언트, 30★, 2026-10-19 생성)과 코어 dinobot-labs/dinobot(Bun 데몬+TUI)을 GitHub API로 구조 분석. 주의 PolyForm Noncommercial 라이선스 — 코드 복사·포팅 불가, 패턴 참고만.

코어에서 발견한 패턴 (구조 실측)

· channels/ — Telegram·Slack·Discord + ask-buttons(채팅 안 승인 버튼)·진행률·쿨다운
· auth/ — 자격증명 풀·로테이션·요청 예산·거절 처리
· core/ — DAG 작업그래프(검증·뷰), 메모리 큐레이터·회고, codemode(샌드박스 코드 실행 워커)
· plugins/ — calendar(플래너)·github·google·image_gen·mcp·pm(작업 원장) 등 10종
· extensions/ — skill-evolution(스킬 자기 개선)·verification·tool-search

데스크톱에서 발견한 패턴

· 얇은 Electron 셸이 로컬 데몬을 확보·기동·동반 재시작(daemon-ensure/process)
· 브라우저 컨트롤러(프로세스·신뢰·검증 분리)
· 아티팩트·첨부·클립보드·이미지 파이프라인
· 스타일가이드+공유 UI 킷(재사용 컴포넌트 회귀)

5. 결론

Grok Bot = 100 기준 68. 그러나 이 숫자보다 중요한 구조: 지는 축(모델·채널·접근성·확장)은 전부 로드맵으로 지워지는 것들(BYO 키, Telegram 2차, Electron, 3차 멀티유저)이고, 이기는 축(주권·통제·개방성·비용)은 클라우드 제품이 구조적으로 따라올 수 없는 것들이다. 1차 목표였던 "로컬에서 진짜 써보기"는 31/31 매트릭스와 실물 E2E로 닫혔고, 2차의 최단 승부처는 Telegram+승인버튼 — 우리 승인 API는 이미 그 버튼을 기다리고 있다.
