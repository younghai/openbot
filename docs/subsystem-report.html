1. 진입 · 부팅 · 라우팅

HOW
  1. 부팅 순서: 디렉터리 확보 → 스킬 시드(예제·desktop-use) → 고아 running 잡 복구(error 처리) → 위임 와이어링 → 크론 스케줄러 → 텔레그램 게이트웨이 → 큐 킥 — apps/server/src/index.ts:24
  2. 라우트는 도메인 8파일로 분할(bots·conversations·computers·models·sources·routines·tasks·platform/files) 후 얇은 컴포저로 마운트 — routes.ts(17줄)
  3. mutation 입력은 zod 계약으로 검증(400 + issues) — 예: routes/conversations.ts:14
  4. 예외는 app.onError가 로깅 후 구조화 500 반환 — index.ts:21
  5. WS 업그레이드는 /ws 단일 경로 — ws.ts:7
WHY

· 분할: 원래 523줄 모놀리식 routes.ts가 도메인 8파일로 나뉨(2026-10-31 리팩토링 패키지) — PM툴급 확장(Task·검색·통계) 전에 갚은 구조 부채.
· onError: 라우트 예외가 무로그 500으로 사라진 실측 사건(/api/bots 디버깅)이 직접 계기.
· 고아 잡 복구: 재시작 전 running 잡이 큐를 영구 봉쇄한 실측 사고(WS봇2 hang)의 근본 수정 — 서버 없이 살아남는 running은 없다는 불변식.
· zod: 손으로 쓴 검증의 비일관성을 계약으로 대체(선언만 되고 안 쓰던 의존성을 실제로 활성화).

닻: index.ts:21,24 · routes/*.ts · ws.ts:7 · 감사: 분할 직후 매트릭스로 34/34 회귀 확인(컴퓨터 라우트 누락·zod 29k 거부를 매트릭스가 잡음)

2. 에이전트 루프 — 대화의 심장

HOW
  1. runAgent: 시스템 프롬프트(페르소나+기억 회상+할당 작업+스킬 목록) 조립 → 최대 12회 모델↔도구 반복 — loop.ts:42,155
  2. 매 턴 시작 시 maybeCompact: 24k자 초과면 오래된 70%를 요약으로 압축(도구 결과도 요약 원문에 보존) — loop.ts:236
  3. historyForProvider: 저장된 행을 공급자용으로 재조립, 이미지 첨부는 image_url 멀티모달 파트로 — loop.ts:327,363

WHY

· 12회 상한: 무한 도구 루프 방지(매트릭스로 상한 동작 확인).
· 압축이 문자수 기반 70%: 로컬 소형 모델 시대의 단순함 우선 — 중요도 기반 선택은 3차 개선(도구 결과 보존)으로 절충.
· 작업을 시스템 프롬프트에 주입: 보드의 "담당 봇"이 자기 작업을 항상 보게 하여 task.update 자가 보고가 자연스럽게 발생(실물 관찰).
· 회상 스코어링: "최신 10개"는 오래된 중요 사실을 묻힘 — ReMe식 지식 우선 회상으로 개선(2026-11-01).
